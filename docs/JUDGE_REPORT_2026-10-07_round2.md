## Key probe results (all performed live)

- **CLOSED via UI only:** created CASE-9007f9a2 (technician) → Advance → mgr1 Approve → Raise Work Order → Record Outcome → Submit Feedback, entirely by click; confirmed server state is `CLOSED` via API.
- **ESCALATED → resolved via UI only:** CASE-7b094af4 (comm-bus failure, G3, "Who to call: Building Management System pill") resolved via the Resolve Escalation reason box → `CLOSED`.
- **Technician tries to approve:** UI shows "Approval Blocked... Role 'tech1' does not have the approve_reject_modify capability"; independently confirmed server-side with `curl`, including a `tech1` cookie + `?user=mgr1` spoof layered on top — still rejected.
- **Steward self-approval:** UI greys the Approve button ("You sent this. A different steward must decide."); clicking it anyway does nothing; `curl` with the steward1 cookie returns `403 "steward1 proposed PROP-... and cannot also approve it"`.
- **Expert capture → later diagnosis reuse:** captured a J. Lim/CRAH interview, steward2 approved it (KB v1.3.0→1.4.0), then a brand-new case (CASE-7e3c321c) showed it under "Expert Knowledge Reused" with correct attribution, knowledge ID, and verbatim quote — the AI-HARVEST loop is real end-to-end.
- **Approve → version bump → rollback:** v1.3.0→1.4.0→1.5.0→1.6.0 via three approvals; admin rollback to "v1.4.0 (version 1)" correctly removed 2 later cases and the dropdown label/int pairing matched exactly — this specific gap from the prior report is now fixed.
- **AI unavailable:** restarted with `TBC_LLM_PROVIDER=adp` and no key — top bar honestly shows "Capture model: Tencent Cloud ADP (key missing)"; second opinion shows an "AI offline" card and the deterministic diagnosis proceeds unaffected; capture instead hard-fails with HTTP 502.
- **Audit tampering:** edited a persisted history record's `reason` directly in `data/tbc.sqlite` (note: a graceful server shutdown autosaves and will silently overwrite a tamper — had to `kill -9` to make it stick); on restart the server logged `invalid audit chains on restore: ['CASE-9007f9a2']`, and the Governance screen's own audit table shows every row for that case as a red **FAIL** chain badge.
- **Unknown asset:** via API only (the UI form has no free-text asset field), `NOPE-999` escalates via G5 with confidence 0.0, never fabricates a diagnosis — but this is **not demoable through the UI alone**.
- **URL identity spoofing:** typed `?user=admin1` directly into the address bar while the browser held a `tech1` session — banner stayed "Technician"; `curl` with no cookie at all and `?user=mgr1` is rejected by default (`TBC_DEMO_INSECURE` unset).
- **Projector readability:** `test_contrast.py` 28/28 passing; both themes visually crisp in direct screenshots.
